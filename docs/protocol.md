# veil protocol (draft)

> Draft, matching the M0 scaffold. Expect changes through M1–M2. **The crypto
> protocol is custom (built on Noise) and unaudited — do not rely on it for
> security-critical use yet.**

## Layers

```
+---------------------------------------------------------------+
|  IP packets (from the TUN device)                             |
+---------------------------------------------------------------+
|  Noise session AEAD  (ChaCha20-Poly1305, per-message nonce)   |   internal/noise
+---------------------------------------------------------------+
|  veil frame          (12-byte header + payload)               |   internal/tunnel
+---------------------------------------------------------------+
|  transport           udp | tcp | tls | wss  (auto-selected)   |   internal/transport
+---------------------------------------------------------------+
```

## 1. Handshake — Noise `IK`

- Pattern: `IK` — the initiator (client) knows the responder's (server's) static
  public key in advance (pinned at enrollment), giving mutual authentication,
  forward secrecy, and initiator identity hiding.
- Primitives: X25519 (DH) · ChaCha20-Poly1305 (AEAD) · SHA-256/BLAKE2s (hash).
- Optional pre-shared key (WireGuard `psk2`-style) mixes in extra entropy.
- Server static keypair is generated by `veil-server init`; its **fingerprint**
  (`internal/noise.Fingerprint`) is shown out-of-band and pinned by the client
  (trust-on-first-use).

## 2. Frame format

Fixed 12-byte big-endian header + payload (see `internal/tunnel/frame.go`):

| offset | size | field   | notes |
|--------|------|---------|-------|
| 0      | 1    | version | currently `1` |
| 1      | 1    | type    | handshake_init / handshake_resp / data / keepalive / close |
| 2      | 8    | counter | per-session monotonic nonce (replay protection + AEAD nonce basis) |
| 10     | 2    | length  | payload length, `0..65535` |
| 12     | N    | payload | for `data`: a Noise-encrypted IP packet |

Datagram transports carry one frame per datagram; stream transports
length-delimit frames with the header's `length` field.

## 3. Transports & auto-selection

Transports are interchangeable (`internal/transport.Dialer`/`Conn`). On connect
the client races them with a staggered start (`internal/transport.Selector`,
"Happy Eyeballs" style), keeps the first that completes a handshake, and — via
`Memory` — remembers the winner per network for instant reconnect. A dead/throttled
transport triggers failover to the next.

| transport | default order | blends as | notes |
|-----------|:-------------:|-----------|-------|
| `udp`     | 1 | — | fastest; default |
| `tcp`     | 2 | — | where UDP is blocked |
| `tls`     | 3 | HTTPS | real cert on :443 |
| `wss`     | 4 | HTTPS/WebSocket | full obfuscation; traverses HTTP proxies + most DPI |

## 4. Anti-probing

The server presents a real Let's Encrypt certificate and a plausible decoy site
at `/`; only requests bearing a valid authenticated upgrade token cross into the
tunnel, so active probers see an ordinary website.
